# Verified RAG: results report

A small cross-encoder sits between retrieval and generation. It scores every retrieved paragraph, makes a CRAG-style decision (correct, ambiguous or incorrect), keeps only the sentences that support the question, rewrites the query when the evidence is weak, and a second small model decides whether the remaining context is enough to answer. When it is not, the system abstains instead of letting the generator guess.

All numbers below come from files in `results/`. The tables in [`report_tables.md`](report_tables.md) are generated by `scripts/report_tables.py` from the metrics JSON, so they can be checked against the source.

## Summary

On 300 held-out HotpotQA questions, each turned into three evidence conditions (839 question/condition pairs), the full system (arm F) was compared with plain hybrid RAG (arm A) using the same generator (Qwen3-4B-Instruct-2507):

| Condition | Hallucination A → F | Paired diff, 95% CI | Correct A → F |
|---|---|---|---|
| supportive (gold paragraphs present) | 24.7% → 18.3% | −6.3 pp [−10.7, −2.0] | 48.7% → 43.7% (−5.0 pp, p = 0.06) |
| missing (gold paragraphs removed) | 8.0% → 0.7% | −7.3 pp [−10.3, −4.7] | 6.7% → 0.3% |
| misleading (answer entity swapped in the gold text) | 24.7% → 17.2% | −7.5 pp [−13.0, −2.1] | 10.0% → 9.6% |

The context sent to the generator shrinks from about 1,070 tokens to about 220. The price is coverage: on supportive questions F answers 62% of the time against 73% for A, and its correct rate falls by 5 points (the CI touches zero). The planted-answer rate on the misleading condition drops only from 30.5% to 27.6%, which is not significant: the system does not detect a fluent paragraph that has been tampered with.

Every threshold, including the abstain threshold, was fixed on the dev split before the test run.

## What was built

```
question
  └─ hybrid retrieval: BM25 (bm25s) + bge-small-en-v1.5, RRF k=60, top 20
      └─ verifier: MiniLM-L6 cross-encoder, fine-tuned, WiSE-FT 0.7, Platt-calibrated
          ├─ decision on max passage probability: correct ≥ 0.65 > ambiguous > 0.15 ≥ incorrect
          ├─ ambiguous/incorrect → LLM writes 2 queries → re-retrieve → re-verify (one round)
          ├─ chunk filter (prob ≥ 0.01, top 8) → sentence refinement (keep prob ≥ 0.05)
          └─ sufficiency model: MiniLM-L12 on (question, numbered context)
              ├─ prob < 0.90 → abstain
              └─ else → generator answers with line citations
```

Every request produces a trace with the scores, the decision, rewritten queries, kept and dropped sentences, the sufficiency probability and per-stage timings. The UI renders these traces.

Arms used in the ablation:

| Arm | Adds |
|---|---|
| A | plain hybrid RAG, top 8 paragraphs |
| B | off-the-shelf reranker (ms-marco-MiniLM-L6-v2) |
| C | our verifier as chunk filter |
| D | C + sentence refinement |
| E | D + CRAG decision with query rewrite |
| F | E + sufficiency gate (full system) |
| G | F with one threshold instead of two |

## Evaluation setup

- **Questions.** HotpotQA distractor setting, a pool of 4,969 paragraphs. 300 test and 200 dev questions, sampled with seed 13. Dev was used for every choice; test was run once at the end.
- **Conditions.** *supportive*: gold paragraphs are in the pool. *missing*: gold paragraphs are removed from retrieval, so abstaining is the right behaviour. *misleading*: the answer entity in the gold text is replaced by an LLM-proposed substitute of the same type (239 of 300 test questions got a valid substitute); answering with the substitute counts as *planted*.
- **Generator.** Qwen/Qwen3-4B-Instruct-2507 served with vLLM 0.32.0 on a Kaggle T4, temperature 0, at most 256 tokens. The same model wrote the query rewrites. All arms share it, and identical prompts were generated once (5,873 traces on test reduced to 3,267 prompts).
- **Outcomes.** abstain; correct (exact match, or the gold answer contained in a short answer); planted; otherwise hallucinate. Containment is token-level and guarded against padded answers.
- **Statistics.** Paired bootstrap over questions, 10,000 resamples, 95% CIs. A `*` in the tables marks a CI that excludes zero.
- **Abstain threshold.** Chosen on dev by a rule written into `PLAN.md` before the dev answers existed: maximise the slice-averaged (correct − hallucinate − planted) over τ ∈ {0.00, 0.05, …, 0.95}, ties to the smaller τ. The sweep (`results/tuning/tau_abstain_dev_main.md`) picked 0.90, mean utility +0.009 against −0.014 at τ = 0.

## QA results on test

Full tables per arm and condition are in [`report_tables.md`](report_tables.md) and `results/qa/test_main/summary.md`. The stage-by-stage comparisons:

**Verifier as a filter (C vs A).** Small changes. On supportive, correct goes from 48.7% to 52.3% and hallucination from 24.7% to 24.3%; context drops from 1,070 to 752 tokens. The off-the-shelf reranker (B) does slightly worse than A on supportive correct (46.7%).

**Sentence refinement (D vs C).** Context falls from 752 to 221 tokens. Hallucination drops on missing (−3.0 pp*) and planted answers drop on misleading (−5.4 pp*). On supportive, correct falls by 4.7 pp (p = 0.055): refinement keeps all supporting facts for only 57% of supportive questions, against 90% before it. On dev the same step gained a point of correct and cut hallucination by 7 points, so the effect on supportive questions is not stable between splits.

**Query rewrite (E vs D).** No measurable effect: every difference is within ±1.3 pp and none is significant. The rewriter was called 0.45 times per supportive question and 0.96 times per missing one, but the share of supportive questions with all supporting facts in the context only moved from 57.3% to 58.0%.

**Sufficiency gate (F vs E).** Every difference is significant. Hallucination falls by 3.3, 4.7 and 5.0 pp on supportive, missing and misleading; planted answers by 2.5 pp. Correct falls by 4.3 pp on supportive and 2.5 pp on misleading. Selective accuracy on supportive goes from 68.9% to 70.4%.

**One threshold vs two (G vs F).** Outcomes within 1 pp of F everywhere; G calls the rewriter far less often (0.03 vs 0.45 calls per supportive question) because its single threshold rarely lands in "ambiguous".

**Risk-coverage.** Sweeping the sufficiency threshold for arm F gives a normalised area under the selective-accuracy curve of 0.734 on supportive, 0.355 on missing and 0.164 on misleading (`results/qa/test_main/summary.md`). On misleading, selective accuracy stays between 10% and 20% at every coverage level, which is the same failure seen in the planted rate.

**Generator caution.** Qwen3-4B already abstains often on its own: arm A abstains on 85% of missing questions and on 27% of supportive ones. That leaves less room for the gate to help than a more confident generator would.

### LLM judge

A judge from another model family (`qwen/qwen3.8-27b` on Groq) graded a stratified sample of 100 answered test questions. It agreed with the deterministic outcome on 85 (Cohen's κ 0.71). All 15 disagreements go the same way: the judge accepts an alias that the metric rejects, for example "Chris Pine" for "Christopher Whitelaw Pine" or "Jersey barriers" for "Jersey barrier". The deterministic metric therefore overstates hallucination for every arm. Arms that answer more often are penalised more in absolute terms, so part of F's hallucination reduction may come from answering less, not only from answering better.

## The verifier

The base checkpoint is `cross-encoder/ms-marco-MiniLM-L6-v2`. The final model is a fine-tune on HotpotQA passages and sentences plus MS MARCO pairs, averaged with the base weights (WiSE-FT, α = 0.7).

| | HotpotQA dev nDCG@10 | SciFact | NFCorpus | FiQA |
|---|---|---|---|---|
| base MiniLM-L6 | 0.897 | 69.6 | 35.8 | 37.1 |
| fine-tuned (v4) | 0.953 | 53.3 | 27.9 | 21.8 |
| **final (v4 + WiSE-FT 0.7)** | 0.941 | 68.0 | 33.8 | 34.0 |
| hybrid retrieval, no reranker | | 72.3 | 36.2 | 36.2 |

BEIR columns are test nDCG@10 ×100 when reranking the hybrid top 50. None of the off-the-shelf rerankers tested (MiniLM-L6, MiniLM-L12, bge-reranker-base) beat the hybrid first stage on SciFact or NFCorpus either, so out-of-domain reranking was a weak spot from the start. The final verifier stays 1.6 to 3.1 points below its base checkpoint on BEIR and gains 0.044 on HotpotQA dev.

Platt calibration brings the expected calibration error from 0.085 to 0.005 for passages and from 0.156 to 0.006 for sentences (dev, 10 bins; question-grouped 5-fold CV gives 0.005 for both). At τ_hi = 0.65, 90.6% of questions labelled "correct" do have a gold paragraph among their candidates.

CPU latency (4 threads, `results/latency.md`): MiniLM-L6 scores 20 passages in 0.79 s and 60 sentences in 0.36 s at the median. L12 takes about twice that, and bge-reranker-base needs 4.4 s for the passages alone.

## The sufficiency model

Training data comes from HotpotQA supporting facts with no LLM labels: *sufficient* (all supporting sentences present among distractors), *missing-hop* (one hop's supporting sentences removed) and *no-evidence* (none present). ROC AUC of sufficient against each negative kind on 600 dev examples (`results/tuning/sufficiency.md`):

| Model | missing-hop | no-evidence | pooled |
|---|---|---|---|
| base ms-marco-MiniLM-L6-v2, no training | 0.866 | 0.974 | 0.920 |
| MiniLM-L6, 60k examples, 1 epoch | 0.886 | 0.989 | 0.937 |
| **MiniLM-L12, 270k examples, 2 epochs** | **0.978** | **0.998** | **0.988** |

The dev examples are built the same way as the training data, so these AUCs measure the proxy task. They do not show that the model detects insufficient context in general. Its failure on the misleading condition is the clearest evidence: a paragraph with a swapped entity is still "sufficient" by construction.

## What went wrong along the way

These are recorded because they changed the design, and the commit history has the details.

**The verifier forgot how to rank outside HotpotQA.** The first fine-tune (lr 2e-5) raised HotpotQA dev passage MAP from 0.82 to 0.93 and dropped SciFact nDCG@10 from 69.6 to 52.7. A lower learning rate (7e-6) and a run without any BEIR training pairs fell just as far, which ruled out ordinary forgetting and BEIR noise. A probe made the cause visible: the fine-tuned model scored a nonsense query against medical abstracts at +0.6, where the base model gave −9.6. HotpotQA's distractors are chosen for word overlap, and bridge-question second-hop paragraphs share almost no words with the question. Training on those labels taught the model that lexical overlap signals irrelevance. Adding easy random negatives (v4) helped a little; interpolating the weights with the base model (WiSE-FT) recovered most of the loss.

**The dev evaluator was measuring the wrong thing.** The early BEIR dev check compared top-graded positives with the hardest unjudged candidates, and by that measure the broken model looked better than the base (NFCorpus MRR 0.575 vs 0.479). In the real ranking it promoted off-topic documents (0.280 vs 0.681). The evaluator was rebuilt to use the same protocol as the test (every judged document in the hybrid top 50 against the unjudged ones), after which dev and test agreed.

**The teacher filter threw away most of the data.** Dropping BEIR negatives that a stronger reranker scored above the weakest positive removed 57% of candidates, 81% on NFCorpus, where bge-reranker-base scores most judged positives near zero. The filter now drops a candidate only when the teacher is confident (p ≥ 0.9) or ranks it above a positive the teacher itself trusts, which removes 1 to 4%.

**One threshold was doing two jobs.** τ_lo decided "incorrect" and also filtered chunks. Supporting facts were in the retrieved top 20 for 97.7% of dev questions, but with the first verifier they survived the filter for only 72.3%, because second-hop paragraphs score low. With a separate chunk threshold (τ_chunk) and the final verifier, the share of dev questions keeping all supporting facts after the filter went from 56% to 89%.

**The LLM budget ran out.** Groq's free tier caps each model at 200,000 tokens a day, about 200 answer calls, so the 5,419 distinct evaluation prompts (dev and test) would have taken about four weeks. Generation and query rewrites moved to an open model on Kaggle (vLLM, batch), with an offline cache mode: `prepare` writes the rewrite requests it cannot serve from cache, Kaggle generates them, and `import-rewrites` stores the outputs under the original request keys. Groq is kept for the live demo and the judge.

## Limitations and deviations from the plan

- **Proxy data.** Sufficiency labels, the misleading condition and the verifier's main training data all come from HotpotQA. The results say little about other domains, and the BEIR numbers show the verifier itself is slightly worse than its base model out of domain.
- **Tampered evidence is not detected.** Planted answers fall by 2.9 pp at most. Detecting a fluent but altered paragraph needs a different signal (cross-source agreement, or a model trained on such edits).
- **Strict correctness metric.** The judge shows that about 15% of answered questions marked hallucinate are alias matches. All arms are affected; the absolute hallucination rates are overstated.
- **Grid-edge fallbacks.** τ_chunk (0.01) and τ_keep (0.05) are at the edge of their grids because no setting reached the 90% recall target. Refinement keeps all supporting facts for only about 57% of supportive questions, which is the likely cause of its unstable effect on correct answers.
- **Rewrite step.** It adds an LLM call for about half the questions and had no measurable effect. With this corpus and a 4B rewriter it could be dropped.
- **Not done from the plan.** The verifier was trained with one seed rather than three. Sufficiency labels came from HotpotQA supporting facts instead of an LLM teacher, so there was no teacher-human agreement check. Faithfulness is measured only through citation validity and citation support, not by a separate claim-level check.
- **Latency.** The batch evaluation reuses retrieval and verifier scores across arms, so its timings are not meaningful. Interactive latency comes from the CPU benchmark above and the live demo.

## Reproducing

`notes/STATE.md` and `PLAN.md` list every command. In short:

```bash
python scripts/run_qa_eval.py prepare --split test --arms A..G --out data/eval/test_main/ \
    --sufficiency data/models/sufficiency-minilm-l12 --overlay configs/tuned.toml \
    --rewrite-model local/Qwen3-4B-Instruct-2507 --offline-rewrites
python scripts/kaggle_job.py prompts data/eval/test_main/prompts.jsonl   # then generate / wait
python scripts/run_qa_eval.py finalize --run data/eval/test_main \
    --outputs data/kaggle/<job>/output/outputs.jsonl --tau-abstain 0.9
python scripts/report_tables.py > results/report_tables.md
```
