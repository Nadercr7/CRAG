# Verified RAG: design brief for the explainer, the slides and the speaker guide

Three deliverables, one visual family:

1. `docs/explainer.html`: a long explainer page. The full explanation in English, then the full explanation again in Egyptian Arabic (RTL), in the same file. The Arabic half is written natively for an Egyptian reader. It is not a line-by-line translation. Audience: anyone, including people with no ML background.
2. `docs/slides.html`: a keyboard-driven presentation in English for a 7-8 person student team presenting their mini project. Heavy on motion and visuals. 16:9 stage scaled to the window.
3. `docs/speaker-guide.html`: a simple Egyptian Arabic page that walks through every slide: what is on it, what to say, and likely questions with answers.

Each final file is one self-contained HTML file (CSS, JS and data inlined by `docs/explain/build.mjs`). External scripts only from cdnjs (pinned versions), fonts only from Google Fonts, with fallbacks so the page still works offline.

## Source of truth

`docs/explain/data.js` sets `window.VRAG_DATA`. It is generated by `scripts/build_explain_data.py` from `results/` and the real traces. **Every number shown on any page comes from `VRAG_DATA` at runtime or is quoted from `results/report.md`.** Never type a number that is not in one of those two places. If a number you want does not exist, leave it out.

Key facts (all in `results/report.md`):
- Test: 300 HotpotQA questions, three evidence conditions (supportive 300, missing 300, misleading 239 = 839 pairs), 5,873 traces, same generator for every arm (Qwen3-4B-Instruct-2507 on Kaggle, vLLM).
- Full system (arm F) vs plain RAG (arm A): hallucination 24.7 -> 18.3 (supportive), 8.0 -> 0.7 (missing), 24.7 -> 17.2 (misleading); paired diffs -6.3 / -7.3 / -7.5 pp, all CIs exclude 0. Context ~1,070 -> ~217 tokens. Cost: supportive correct 48.7 -> 43.7 (-5.0 pp, p = 0.06), coverage 73 -> 62. Planted answers 30.5 -> 27.6 (not significant). Rewrite step: no measurable effect.
- Thresholds: tau_hi 0.65, tau_lo 0.15 (decision), tau_keep 0.05 (sentences), tau_abstain 0.90 (chosen on dev by a rule written down before the dev answers existed).
- Verifier: MiniLM-L6 cross-encoder fine-tuned on HotpotQA + MS MARCO, then WiSE-FT (alpha 0.7) with the base weights. The plain fine-tune broke out-of-domain ranking (SciFact 69.6 -> 53.3 nDCG@10); averaging brought it back to 68.0. Calibration ECE 0.085 -> 0.005 (passages).
- Sufficiency model: MiniLM-L12 on 270k HotpotQA-derived examples; dev AUC 0.978 (missing-hop), 0.998 (no-evidence).
- LLM judge (qwen3.8-27b) on 100 test answers: 85% agreement, kappa 0.71; all 15 disagreements were aliases (e.g. "Chris Pine" vs "Christopher Whitelaw Pine") that our strict metric called hallucinations.
- Infrastructure: Groq free tier capped at 200k tokens/day per model, so bulk generation moved to Kaggle (2x T4, vLLM); 5,873 test traces deduplicated to 3,267 prompts.

## The concept: an inspection line

Verified RAG is explained as a **quality-control line**. Paragraphs come in like parts on a bench. A gauge measures each one (the verifier score, 0 to 1). A sorting gate puts the question into Correct / Ambiguous / Incorrect (the two thresholds). Ambiguous sends a ticket back to search again with a rewritten query. A trimming press cuts each paragraph down to the sentences that matter. A scale weighs what is left against the 0.90 line (sufficiency). Then either the answer is stamped with its citations, or the line stops and stamps "I don't know".

The big idea, in one line: **check the evidence before you answer, and say "I don't know" when it isn't there.**

The plain-RAG baseline is the same bench with every station switched off: whatever search returns goes straight to the answer model.

## Visual identity

Tokens are in `docs/explain/tokens.css`; import it first and build everything from those variables.

- **Paper and ink.** Cool drafting paper with navy ink in light; deep slate with pale ink in dark. Light and dark both ship; respect `prefers-color-scheme` and offer a toggle (`data-theme` on `<html>`).
- **Signal colours carry state only:** pass (correct/kept), hold (ambiguous/rewrite), reject (incorrect/dropped/hallucinated), plant (planted answer), abstain (a calm grey: abstaining is a decision, not an error). Every state also carries an icon or a word, never colour alone.
- **One accent** (inspection blue) for interactive elements and the single thing the eye should follow.
- **Type:** IBM Plex Sans Condensed for display (industrial label feel, used with restraint), IBM Plex Sans for body, IBM Plex Mono only for gauge readouts and numbers that are measurements, IBM Plex Sans Arabic for Arabic. Load from Google Fonts: `family=IBM+Plex+Sans+Condensed:wght@500;600;700&family=IBM+Plex+Sans:ital,wght@0,400;0,500;0,600;1,400&family=IBM+Plex+Mono:wght@400;500&family=IBM+Plex+Sans+Arabic:wght@400;500;600;700&display=swap`.
- **Avoid:** cream + terracotta, purple gradients, the SaaS card kit, all-caps eyebrow labels over every heading, emoji as icons, "A · B · C" meta strings, arrows appended to button text, decorative numbering where order means nothing. Numbered markers are fine for the pipeline steps because they are a real sequence.
- **Icons:** inline SVG, drawn in the same stroke weight as the ink (1.5px), no icon font, no emoji.

## The machine (shared component)

`docs/explain/machine/` builds `machine.js` + `machine.css`, an interactive figure of the inspection line in the anatomy style (isometric, many small parts, a window into the working station, gauges driven by real numbers). Contract, used by both the explainer and the slides:

```js
const m = window.VRAGMachine.mount(containerEl, {
  data: window.VRAG_DATA,     // reads data.scenarios[scenario]
  scenario: "support",        // support | missing | fooled | fail | cost
  lang: "en",                 // "en" | "ar": hints, button labels, sound words
  mode: "manual",             // "manual" (wait for each press) | "auto" (loops)
  controls: true,             // render its own step buttons, scenario picker, mode switch
});
m.go(stepIndex); m.next(); m.reset(); m.setScenario(key); m.setLang(lang); m.setMode(mode);
m.on("step", ({ index, id }) => {}); m.destroy();
```

Steps (ids): `ask`, `search`, `inspect`, `decide`, `trim`, `weigh`, `answer`. Only the next step is clickable in manual mode. Hints are simple enough for a 12-year-old. Every number on the figure comes from the scenario's trace.
