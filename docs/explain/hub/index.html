Verified RAG

A language model that answers from search results will trust whatever the search hands it. This project puts a small model between the search and the answer. It checks each paragraph, keeps only the sentences that matter, and says “I don’t know” when the evidence isn’t enough.

A mini project, tested once on 300 held-out HotpotQA questions, each asked three ways: with the evidence, with the evidence removed, and with a wrong answer planted in it.

What it changed, against plain RAG

−6.3 to −7.5points of made-up answers in all three test conditions (each 95% interval excludes zero)
1,070 → 217tokens of context sent to the answer model, on average
−5.0points of correct answers when the evidence was there: it answers less often (p = 0.06)

It does not catch a fluent paragraph with a swapped answer, and the query-rewrite step had no measurable effect. Both are in the report.

Run it

# Python 3.12+
git clone https://github.com/Nadercr7/CRAG.git && cd CRAG
pip install -e ".[dev,eval]"
pytest                              # unit tests, no network
uvicorn vrag.api.app:app            # UI at http://127.0.0.1:8000

The dashboard and the 22 example traces work from a fresh clone. Live questions also need the trained models, the search index and a Groq API key; the README explains each. The models are in a private Kaggle dataset (ask for access) or can be retrained with the Kaggle jobs in scripts/kaggle_job.py.

Built on CRAG (Yan et al., 2024) and Sufficient Context (Joren et al., ICLR 2025). Data: HotpotQA, BEIR, MS MARCO. Answers generated by Qwen3-4B-Instruct on Kaggle.
